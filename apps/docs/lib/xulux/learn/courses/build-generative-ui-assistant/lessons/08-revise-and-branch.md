# Revise and branch a conversation

This final stage adds message editing, regeneration, and branch navigation as one connected capability.

Explain that editing an earlier user message or regenerating an assistant response does not have to destroy the original path. The runtime can retain alternate branches, while the thread UI exposes actions and a branch picker for navigating them.

Ask the learner to start with the Branch a response suggestion, edit that prompt, compare the new response with the original branch, regenerate once, and move between the available alternatives.

Close by recapping the application: streamed chat, guided suggestions, structured tools, deterministic tool UI, shared editable state, persisted conversations, and branches. Attachments, model selection, voice, and managed cloud persistence are natural next directions, not additional requirements for this course.
