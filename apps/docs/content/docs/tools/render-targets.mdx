The same generative-UI tree renders on more than one surface. On the web the
[default vocabulary](/docs/tools/generative-ui) renders as React components;
`@assistant-ui/react-generative-ui/slack` and
`@assistant-ui/react-generative-ui/teams` convert the tree outward to Slack
Block Kit and Microsoft Teams Adaptive Cards; and
`@assistant-ui/react-generative-ui/a2ui` converts inward, mapping
[A2UI surfaces](/docs/tools/a2ui) onto the same vocabulary.

This page is the index across those surfaces, not a second copy of them. What
each component becomes on Slack or Teams, and what that costs, is documented
once on the platform guides — the rows below link straight into them. What this
page adds is the two things neither guide can show on its own: whether a
degradation is reported to you or happens silently, and which A2UI component
ingests into each vocabulary component.

## Capability matrix

Both outbound converters are total: they never throw, and a degradation comes
back as a structured warning (`SlackConversionWarning` /
`TeamsConversionWarning`) instead. That is a statement about not throwing
rather than about coverage — each guide's own fidelity rows also describe
degradations that happen *silently*, in those words. Which of the two you get
decides whether a production surprise shows up in your logs or only in a
screenshot, so the markers below collect the guides' warning wording per
component:

- **warns** — the guide describes a warning for at least one of this
  component's degradations on that target.
- **silent** — the guide describes at least one of them as silent.
  These are the rows worth following before you ship.

A row can carry both. An unmarked cell is not a fidelity guarantee: it means
the guide's row for that component describes no loss, or — for the four rows
noted below the table — that its wording is still being corrected. The A2UI
column reads in the opposite direction: it
lists which A2UI component produces that vocabulary component when a surface is
ingested.

27 vocabulary components × 4 targets. Markers describe warning behavior only;
the linked guide is the authority on what each component becomes and what the
loss is. Slack's `Header`, `Text`, and `Divider` rows and the Teams `Header`
row carry no marker, because the guides' wording for those rows is itself being
corrected right now, in
[#5824](https://github.com/assistant-ui/assistant-ui/pull/5824) and
[#5825](https://github.com/assistant-ui/assistant-ui/pull/5825). A marker
follows the guide; it does not get out ahead of it.

One warning code carries a meaning the markers cannot: Teams' `advisory`
reports that nothing was changed at all, so unlike every other code it is a
heads-up rather than a record of a loss
([Teams limits](/docs/tools/generative-ui-teams#limits)).

## Interaction model differences

The four targets do not agree on when a control dispatches, and that is the
part a tree author cannot see from any single guide.

- **Web** dispatches `$action` payloads directly through the action registry.
- **Slack** round-trips actions through `block_actions` webhooks; decode each
  entry with `decodeBlockAction`. `Input` is the one control that does not
  dispatch on interaction, so a typed value never arrives as a `block_actions`
  entry and `decodeBlockAction` never sees it — read it from the payload's
  `state.values` next to the action that submitted.
- **Teams** inputs cannot dispatch on change: an input carrying an `$action`
  gets a companion Submit action appended, and all values arrive together in
  the submit payload for `decodeSubmitData`.
- **A2UI** actions arrive as `a2ui:action` payloads carrying the surface and
  source component ids.

Reading a surface back is a third direction again: `fromSlackBlocks` parses a
Block Kit message into vocabulary nodes rather than decoding an interaction,
and it has no Teams counterpart.

## Known gaps

None of these fails a conversion — they degrade or drop as the guides describe.
The **silent** markers above double as a warning-coverage roadmap: those losses
are documented in prose, but nothing about them reaches your logs at runtime.

- **Thinking steps / task cards** (agent progress surfaces) are not part of the
  vocabulary yet, so no target can render them. Direction discussion:
  [assistant-ui#5623](https://github.com/assistant-ui/assistant-ui/issues/5623).
- **A2UI ingest** covers the 9 components in the A2UI column above (see
  [Component mapping](/docs/tools/a2ui#component-mapping) for the per-component
  rules); other A2UI components are skipped with a warning, and there is no
  outbound assistant-ui → A2UI converter.
- **Slack `Input` values** have no decoder in the package: the converter emits
  no `dispatch_action`, and `decodeBlockAction` reads action entries only, so
  pulling typed values out of `state.values` is left to your webhook handler.
