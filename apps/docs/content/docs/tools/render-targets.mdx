The same generative-UI tree renders on more than one surface. On the web the
[default vocabulary](/docs/tools/generative-ui) renders as React components;
`@assistant-ui/react-generative-ui/slack` and
`@assistant-ui/react-generative-ui/teams` convert the tree outward to Slack
Block Kit and Microsoft Teams Adaptive Cards; and
`@assistant-ui/react-generative-ui/a2ui` converts inward, mapping
[A2UI surfaces](/docs/tools/a2ui) onto the same vocabulary.

Both outbound converters are total: they never throw. Many lossy steps are
reported as a structured warning (`SlackConversionWarning` /
`TeamsConversionWarning` with a `code` of `clamped`, `fallback`, `dropped`, or,
on Teams only, `advisory`),
but not all of them — the matrix marks each degradation as *(warns)* or
*(silent)* so you know which losses your warning log will actually show.

## Capability matrix

Legend: **Yes** — maps to a native construct. **Degrades** — converts, but to
a simpler output shape; the note says what is lost, and *(warns)* / *(silent)*
says whether a warning is emitted for it. **Note** — replaced by a visible
omission note plus a `dropped` warning. **—** — no counterpart on that surface
(dropped silently outbound; never produced inbound).

The A2UI column reads in the opposite direction: it lists which A2UI component
produces that vocabulary component when a surface is ingested.

27 vocabulary components × 4 targets. Slack and Teams caps (block counts,
option counts, text lengths, table sizes) clamp with a warning rather than emit
an invalid payload. The wiring, the webhook decoding (`decodeBlockAction` and
`decodeSubmitData`; the separate `fromSlackBlocks` parses a Block Kit message
back into vocabulary nodes rather than decoding an interaction), and the full
caveat prose behind these cells live in the
[Generative UI on Slack](/docs/tools/generative-ui-slack) and
[Generative UI on Microsoft Teams](/docs/tools/generative-ui-teams) guides —
including the two budgets that behave unlike the rest: the `data_table`
character budget every table in one conversion shares, and the Teams payload
check that only measures.

## Interaction model differences

- **Web** dispatches `$action` payloads directly through the action registry.
- **Slack** round-trips actions through `block_actions` webhooks; decode each
  entry with `decodeBlockAction`. Only the controls that land in an `actions`
  block (`Button`, `Select`, `RadioGroup`, `Checkbox`, `DatePicker`, and a
  `Form`'s submit button) dispatch on interaction. `Input` is the exception: it
  becomes an `input` block with no `dispatch_action`, so a typed value never
  arrives as a `block_actions` entry and `decodeBlockAction` never sees it —
  read it from the payload's `state.values` next to the action that submitted.
- **Teams** inputs cannot dispatch on change: an input carrying an `$action`
  gets a companion Submit action appended (reported as a `fallback` warning),
  and all values arrive together in the submit payload for `decodeSubmitData`.
- **A2UI** actions arrive as `a2ui:action` payloads carrying the surface and
  source component ids.

## Known gaps

These rows feed the roadmap; none of them fail a conversion — they degrade or
drop as listed above. The *(silent)* degradations in the matrix are also
candidates for warning coverage: today the only record of those losses is this
page.

- **`Chart`** has no Slack Block Kit or Adaptive Cards mapping; both targets
  emit an omission note instead.
- **Thinking steps / task cards** (agent progress surfaces) are not part of the
  vocabulary yet, so no target can render them. Direction discussion:
  [assistant-ui#5623](https://github.com/assistant-ui/assistant-ui/issues/5623).
- **A2UI ingest** covers the 9 components in the A2UI column above (see
  [Component mapping](/docs/tools/a2ui#component-mapping) for the per-component
  rules); other A2UI components are skipped with a warning, and there is no
  outbound assistant-ui → A2UI converter.
- **Slack `Input` values** have no decoder in the package: the converter emits
  no `dispatch_action`, and `decodeBlockAction` reads action entries only, so
  pulling typed values out of `state.values` is left to your webhook handler.
- **Slack layout** is single-column: `Row`, `Col`, and `Box` flatten because
  Block Kit has no general column construct.
