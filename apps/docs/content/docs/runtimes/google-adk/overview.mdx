`@assistant-ui/react-google-adk` integrates with [Google ADK JS](https://github.com/google/adk-js), Google's official agent framework for TypeScript, and works with ADK Python backends as well. It supports streaming text, tool calls, multi-agent orchestration, code execution, session state, tool confirmations, auth flows, and input requests.

## When to use it

Pick the Google ADK runtime when:

- You are building agents with ADK JS (`LlmAgent`, sequential / parallel / loop agents) or ADK Python.
- You want support for ADK's HITL (human-in-the-loop) primitives: tool confirmations, auth credential flow, workflow input requests.
- You need multi-agent author and branch tracking, agent transfer events, and grounding / citation metadata.

## Quickstart

You need a Google ADK agent running on a server (ADK JS or ADK Python) and React 18 or 19 (React Ink needs React 19).

### Create a backend API endpoint

Use `createAdkApiRoute` to create an API route.
For React Native and Ink, host this route in a separate backend project and
point the client runtime at its absolute URL.

```ts title="app/api/chat/route.ts"
import { createAdkApiRoute } from "@assistant-ui/react-google-adk/server";
import { InMemoryRunner, LlmAgent } from "@google/adk";

const agent = new LlmAgent({
  name: "my_agent",
  model: "gemini-3.8-flash",
  instruction: "You are a helpful assistant.",
});

const runner = new InMemoryRunner({ agent, appName: "my-app" });

export const POST = createAdkApiRoute({
  runner,
  userId: "local-user",
  sessionId: (_req, clientSessionId) => {
    if (!clientSessionId) throw new Error("Missing ADK session ID");
    return clientSessionId;
  },
});
```

`createAdkStream` sends the initialized assistant-ui thread ID as
`clientSessionId`. When the runner exposes `appName` and `sessionService`, the
route creates the corresponding ADK session before the first run. The static
user above is suitable only for local, single-user development. Before
deployment, resolve `userId` from your authentication system: the client-sent ID
selects a conversation, but does not authorize access to it.

</Step>

### Set up the client runtime

Use `createAdkStream` to connect to your API route. It parses the SSE stream for you:

<PlatformTabs>
<Tab value="React">

```tsx title="components/MyAssistant.tsx"
"use client";

import { AssistantRuntimeProvider } from "@assistant-ui/react";
import {
  useAdkRuntime,
  createAdkStream,
} from "@assistant-ui/react-google-adk";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";

export function MyAssistant() {
  const runtime = useAdkRuntime({
    stream: createAdkStream({ api: "/api/chat" }),
  });
  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <Thread />
    </AssistantRuntimeProvider>
  );
}
```

## Adding adapters

Attachment, speech, dictation, voice, and feedback adapters go in the `adapters` option. See [adapters](/docs/concepts/adapters):

```tsx
const runtime = useAdkRuntime({
  stream: createAdkStream({ api: "/api/chat" }),
  adapters: { attachments, speech, feedback },
});
```

For multi-thread, see [threads](/docs/concepts/threads).


## ADK JS and Python servers

No configuration is needed; connect to either ADK JS or ADK Python servers, both of which send camelCase JSON. A backend that sends snake_case field names instead, such as a custom server serializing with pydantic's default `model_dump()`, works too: the package normalizes them in events, message parts, and artifact responses (`function_call` → `functionCall`, `inline_data` → `inlineData`, `mime_type` → `mimeType`, `file_data` → `fileData`, `file_uri` → `fileUri`, `requested_tool_confirmations` → `requestedToolConfirmations`).
