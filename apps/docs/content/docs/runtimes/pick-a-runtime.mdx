A runtime is the connection between assistant-ui's UI primitives and your AI backend. Pick one by the framework you use or by what you need.

## By framework

If you already use one of these frameworks, pick its runtime.

## Your own backend

Use one of these when your backend is not a framework with a runtime above, such as your own REST API or an agent that keeps its own state. The components and adapters work the same; what changes is how messages reach the runtime. [Runtime](/docs/concepts/runtime) explains the two core runtimes they build on.

| Path | Built on | You provide | Choose when |
| --- | --- | --- | --- |
| [`LocalRuntime`](/docs/runtimes/custom/local-runtime) | Core | A `ChatModelAdapter.run` function | You have a `fetch` call to make and want assistant-ui to keep the state |
| [`ExternalStoreRuntime`](/docs/runtimes/custom/external-store) | Core | Your messages and a handler per action | Your messages already live in Redux, Zustand, TanStack Query or similar |
| [`DataStream`](/docs/runtimes/custom/data-stream) | `LocalRuntime` + protocol | A backend that streams the data stream protocol | You want a thin message-stream contract, or you are moving off AI SDK v4 |
| [`AssistantTransport`](/docs/runtimes/custom/assistant-transport) | `ExternalStoreRuntime` + protocol | A backend that streams its agent state | Your agent has state worth showing, or you need commands of your own |

A Python backend can serve either protocol with the [`assistant-stream`](https://pypi.org/project/assistant-stream/) package: `create_run` runs your callback and `DataStreamResponse` streams the result. The DataStream and AssistantTransport pages show the setup for each.

```text
is your backend one of the frameworks above (AI SDK, LangGraph, LangChain, Eve,
Google ADK, A2A, AG-UI, OpenCode, Mastra, OpenAI Agents, Pydantic AI, Cloudflare
Agents, Claude Managed Agents)?
└── yes → use its runtime or guide above
└── no → continue
    │
    do you already have message state in redux / zustand / tanstack-query?
    └── yes → ExternalStoreRuntime
    └── no → continue
        │
        do you control the backend wire format?
        └── yes, and i want simple fetch calls → LocalRuntime
        └── yes, and i want to stream a structured agent state → AssistantTransport
        └── no, the backend already speaks data stream protocol → DataStream
```

## Concepts that apply to every runtime

Whichever runtime you pick, the components see the same [runtime](/docs/concepts/runtime) state, the same [messages and parts](/docs/concepts/messages) and the same [threads](/docs/concepts/threads), and [adapters](/docs/concepts/adapters) work the same way wherever a runtime supports them. APIs prefixed with `unstable_` may change in any release; see [stability](/docs/migrations/stability).
