---
title: Custom backend
description: Connect assistant-ui to a backend that has no framework adapter, using one of four runtime patterns for local state, external stores, and two wire protocols.
---

Use this section when your backend is not one of the frameworks assistant-ui has an adapter for, such as your own REST API or an agent that keeps its own state. The components and adapters work the same as with a framework runtime. What changes is how messages reach the runtime: you write the call yourself, you hand over messages you already store, or your backend sends one of two protocols. All four paths build on the two core runtimes described in [runtime architecture](/docs/runtimes/concepts/architecture).

## The four paths

| Path | Layered on | Wire shape | Choose when |
| --- | --- | --- | --- |
| [`LocalRuntime`](/docs/runtimes/custom/local-runtime) | Core | You write a `ChatModelAdapter.run` function | The simplest case: you have a `fetch` call to make, want assistant-ui to handle state |
| [`ExternalStoreRuntime`](/docs/runtimes/custom/external-store) | Core | You provide messages + callbacks | You already have state in redux, zustand, tanstack-query, or anywhere |
| [`DataStream`](/docs/runtimes/custom/data-stream) | LocalRuntime + protocol | Your backend emits the data stream protocol | You want a thin message-stream contract, or you are migrating from AI SDK v4 |
| [`AssistantTransport`](/docs/runtimes/custom/assistant-transport) | ExternalStoreRuntime + protocol | Your backend streams agent state snapshots | Your agent has rich internal state and you want it surfaced in the UI; or you need bidirectional commands |

## Decision tree

```text
is your backend AI SDK v5 or later, LangGraph, Google ADK, A2A, AG-UI, Eve or OpenCode?
└── yes → use that framework adapter; you do not need this section
└── no → continue
    │
    do you already have message state in redux / zustand / tanstack-query?
    └── yes → ExternalStoreRuntime
    └── no → continue
        │
        do you control the backend wire format?
        └── yes, and i want simple fetch calls → LocalRuntime
        └── yes, and i want to stream a structured agent state → AssistantTransport
        └── no, the backend already speaks data stream protocol → DataStream
```

## Common building blocks

Regardless of which path you pick, the [adapter](/docs/runtimes/concepts/adapters) and [thread](/docs/runtimes/concepts/threads) interfaces work the same way. Wire attachments, history, speech, feedback, suggestions, and multi-thread support through those shared contracts.
