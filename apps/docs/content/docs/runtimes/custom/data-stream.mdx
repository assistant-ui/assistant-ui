---
title: Data Stream Protocol
description: Standard message-streaming protocol on top of LocalRuntime.
---

`@assistant-ui/react-data-stream` consumes the data stream protocol, a standardized format for streaming AI responses. It is layered on `LocalRuntime` (see [architecture](/docs/concepts/runtime)), so all `LocalRuntime` features apply.

The protocol supports streaming text, tool calls, conversation context, error handling, cancellation, and attachments.

## When to use it

Pick this runtime when:

- Your backend already speaks the data stream protocol (or you can make it do so).
- You want a thin message-stream contract without writing a `ChatModelAdapter`.
- You are migrating from AI SDK v4 and want the v4 pattern preserved (see [v4 docs](/docs/runtimes/ai-sdk/v4-legacy)).

If your backend exposes a richer state surface, consider [`AssistantTransport`](/docs/runtimes/custom/assistant-transport) instead.

## Wire protocols

`useDataStreamRuntime` accepts two wire formats. When `protocol` is omitted, it
detects known Vercel AI response markers before falling back to UI message
stream for compatibility.

| Protocol | Detection | Matching backend |
| --- | --- | --- |
| `"ui-message-stream"` | `x-vercel-ai-ui-message-stream: v1`, otherwise fallback | AI SDK v5+'s `result.toUIMessageStreamResponse()` (SSE) |
| `"data-stream"` | `x-vercel-ai-data-stream: v1` | `createAssistantStreamResponse` from `assistant-stream`, or AI SDK v4's `toDataStreamResponse()` (Vercel data stream v1) |

Set `protocol` explicitly only for custom endpoints that do not preserve or
expose the response marker.

### Create the backend endpoint

Your backend should accept POST requests and return data stream responses.
For React Native and Ink, host this endpoint in a separate backend project and
point the client runtime at its absolute URL.

```ts title="app/api/chat/route.ts"
import { createAssistantStreamResponse } from "assistant-stream";

export async function POST(request: Request) {
  const { messages, tools, system, threadId } = await request.json();

  return createAssistantStreamResponse(async (controller) => {
    const stream = await processWithAI({ messages, tools, system });
    for await (const chunk of stream) {
      controller.appendText(chunk.text);
    }
  });
}
```

The request body includes `messages`, `tools`, `system` (if configured), and `threadId`.

A Python backend can stream the same format with the [`assistant-stream`](https://pypi.org/project/assistant-stream/) package: `create_run` hands your callback a `RunController` (`append_text`, `append_reasoning`, `add_tool_call`), and `DataStreamResponse` encodes the run as a Starlette response for FastAPI. That response doesn't send the `x-vercel-ai-data-stream` header, so set `protocol: "data-stream"` on `useDataStreamRuntime`.

```python title="main.py"
from assistant_stream import RunController, create_run
from assistant_stream.serialization import DataStreamResponse
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class ChatRequest(BaseModel):
    messages: list[dict]


async def call_your_model(messages: list[dict]):
    # Replace with your model's streaming call.
    yield "Hello from Python"


@app.post("/api/chat")
async def chat(request: ChatRequest):
    async def run(controller: RunController):
        async for text in call_your_model(request.messages):
            controller.append_text(text)

    return DataStreamResponse(create_run(run))
```

`createAssistantStreamResponse` returns a standard Web `Response`. It drops into any Fetch-style route (Next.js App Router, Hono, Bun.serve, Deno, Cloudflare Workers). On frameworks that use their own response object (Express, Fastify), copy `status` and `headers` over, then pipe `response.body` into the framework's writable stream. Avoid sending the `Response` body into a `res` object whose lifecycle is already controlled by the framework (that is the `ERR_INVALID_STATE: Controller is already closed` failure mode).

## Headers and authentication

```tsx
const runtime = useDataStreamRuntime({
  api: "/api/chat",
  headers: { Authorization: `Bearer ${token}`, "X-Custom-Header": "value" },
  credentials: "include",
});
```

Evaluate per-request:

```tsx
const runtime = useDataStreamRuntime({
  api: "/api/chat",
  headers: async () => ({
    Authorization: `Bearer ${await getAuthToken()}`,
  }),
  body: async () => ({
    requestId: crypto.randomUUID(),
    timestamp: Date.now(),
    signature: await computeSignature(),
  }),
});
```

A `body` callback receives `{ threadId }`, the remote id of the thread being run when a thread list adapter has assigned one, so a request can carry it under the field name your endpoint expects.

## Event callbacks

```tsx
const runtime = useDataStreamRuntime({
  api: "/api/chat",
  onResponse: (response) => console.log("status:", response.status),
  onFinish: (message) => console.log("done:", message),
  onError: (error) => console.error(error),
  onCancel: () => console.log("cancelled"),
});
```

## Tool integration

<Callout type="warn">
Human-in-the-loop tools (`unstable_humanToolNames`, `human()` interrupts) are not supported in the data stream runtime. Use [`LocalRuntime`](/docs/runtimes/custom/local-runtime#human-in-the-loop-tools) directly if you need them.
</Callout>

A tool the server gates with the AI SDK's `needsApproval` shows its approval request on the tool call, and the next request carries the user's decision back to the server.

### Frontend tools

Register tools with `Tools({ toolkit })`, as [Defining tools](/docs/tools/defining-tools#registering-a-toolkit-with-tools) describes. On every request the runtime sends `tools`, a record keyed by tool name whose values hold `description` and a JSON Schema `parameters` object, and it runs a frontend tool's `execute` in the client when the stream calls it:

```tsx title="app/toolkit.ts"
import { defineToolkit } from "@assistant-ui/react";
import { z } from "zod";

export const toolkit = defineToolkit({
  get_weather: {
    type: "frontend",
    description: "Get current weather",
    parameters: z.object({ location: z.string() }),
    execute: async ({ location }) => {
      const weather = await fetchWeather(location);
      return `Weather in ${location}: ${weather}`;
    },
    renderText: { running: "Checking the weather…", complete: "Weather ready" },
  },
});
```

```tsx title="app/page.tsx"
const config = AuiConfig({ tools: Tools({ toolkit }) });

<AssistantRuntimeProvider runtime={runtime} config={config}>
  <Thread />
</AssistantRuntimeProvider>
```

Import `defineToolkit`, `AuiConfig`, and `Tools` from your platform's package (`@assistant-ui/react`, `@assistant-ui/react-native`, or `@assistant-ui/react-ink`). Do not pass `tools` through the `body` option: `body` is merged last, so a `tools` key there replaces the schemas the runtime collected. If you compile the toolkit with `"use generative"`, the client build leaves out the schemas of frontend tools and assumes your server imports the same file. A backend that only reads this request body needs the `backendless` build option, described in [Running without your own backend](/docs/tools/defining-tools#running-without-your-own-backend).

### Backend tool processing

```ts title="Backend tool handling"
const { tools } = await request.json();
const response = await ai.generateText({ messages, tools: toProviderTools(tools) });
```

`toProviderTools` stands for your own conversion from the `tools` record to the format your provider expects. Tool results stream back automatically.

## Message conversion

### Generic (recommended)

```tsx
import { toGenericMessages, toToolsJSONSchema } from "assistant-stream";

const genericMessages = toGenericMessages(messages);
const toolSchemas = toToolsJSONSchema(tools);
```

`GenericMessage` is a union of `system`, `user` (with text and file parts), `assistant` (with text and tool-call parts), and `tool` (with tool-result parts). Convert it to the format your LLM provider expects.

### AI SDK specific

```tsx
import { toLanguageModelMessages } from "@assistant-ui/react-data-stream";

const languageModelMessages = toLanguageModelMessages(messages, {
  unstable_includeId: true,
});
```

`toLanguageModelMessages` internally uses `toGenericMessages` with AI-SDK-specific transformations. For new integrations prefer `toGenericMessages` directly.

## Assistant Cloud integration

```tsx
import { useCloudRuntime } from "@assistant-ui/react-data-stream";

const runtime = useCloudRuntime({
  cloud: assistantCloud,
  assistantId: "my-assistant-id",
});
```

`useCloudRuntime` runs an [Assistant Cloud assistant](/docs/cloud/assistants) on the active thread. It accepts the same options as `useDataStreamRuntime` apart from `api`, `protocol`, `headers`, and `body`, which the assistant supplies.

## LocalRuntimeOptions

`useDataStreamRuntime` accepts every `LocalRuntimeOptions` option in addition to its own. The `chatModel` adapter slot is handled internally and cannot be overridden.

```tsx
const runtime = useDataStreamRuntime({
  api: "/api/chat",
  initialMessages: [
    { role: "user", content: [{ type: "text", text: "Hello" }] },
    { role: "assistant", content: [{ type: "text", text: "Hi!" }] },
  ],
  maxSteps: 5,
  cloud, // see "AssistantCloud" in /docs/concepts/threads
  adapters: {
    attachments: myAttachmentAdapter,
    history: myHistoryAdapter,
    speech: mySpeechAdapter,
    feedback: myFeedbackAdapter,
    suggestion: mySuggestionAdapter,
  },
});
```

See [adapters](/docs/concepts/adapters) for adapter contracts and [LocalRuntime](/docs/runtimes/custom/local-runtime) for inherited options.

## Error handling

The runtime handles common error scenarios automatically:

- Network errors: the message ends with an `incomplete` status that carries the error, and `onError` is called. The request is not retried.
- Stream interruptions: partial content is preserved.
- Tool execution errors: displayed in the UI with error states.
- Cancellation: the request is aborted through its abort signal, and `onCancel` is called.
