title: Flue Runtime
description: Connect a durable Flue agent conversation to assistant-ui with useFlueRuntime.

`@assistant-ui/react-flue` adapts Flue's materialized conversation state to assistant-ui's `ExternalStoreRuntime`. Flue owns durable history and live delivery while assistant-ui renders the conversation, composer, tool calls, reasoning, files, and custom `data-*` parts.

## When to use it

Choose this runtime when:

- Your agent runs on [Flue](https://flueframework.com/) and its conversation URL is the source of truth.
- A browser should reconnect to the same durable history after a reload.
- You want Flue tool activity and `data-*` parts to render through assistant-ui's tool and data UI APIs.

## Runtime setup

```tsx title="runtime-provider.tsx"
"use client";

import { AssistantRuntimeProvider } from "@assistant-ui/react";
import { useFlueRuntime } from "@assistant-ui/react-flue";

export function RuntimeProvider({
  conversationId,
  children,
}: {
  conversationId: string;
  children: React.ReactNode;
}) {
  const runtime = useFlueRuntime({
    url: `/api/agents/support/${conversationId}`,
  });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      {children}
    </AssistantRuntimeProvider>
  );
}
```

The URL identifies one caller-owned Flue conversation. Keep its id in your route, application state, or local storage to reconnect after navigation or reload.

## Message and lifecycle mapping

- Text and reasoning preserve their streaming state.
- Dynamic tools preserve input, output, errors, and Flue duration metadata.
- `data-foo` becomes an assistant-ui data part named `foo`.
- Flue failures become an incomplete assistant message status.
- Composer cancellation calls the conversation's Flue `abort` route.
- `useFlueRuntimeExtras()` exposes the underlying status, error, history readiness, failed sends, settlements, messages, and refresh action.

Flue currently accepts image attachments only. Add `SimpleImageAttachmentAdapter` to the runtime's `adapters.attachments` option when the composer should accept images.

## Authentication

For authenticated routes or custom headers, install `@flue/sdk`, memoize a Flue client, and pass it instead of `url`:

<InstallCommand npm={["@flue/sdk"]} />

```tsx
import { createFlueClient } from "@flue/sdk";
import { useMemo } from "react";

const client = useMemo(
  () =>
    createFlueClient({
      url: `/api/agents/support/${conversationId}`,
      token,
    }),
  [conversationId, token],
);

const runtime = useFlueRuntime({ client });
```

Conversation enumeration, titles, and deletion remain application concerns. The adapter intentionally represents one durable Flue conversation rather than inventing a parallel thread store.
