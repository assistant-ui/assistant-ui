---
title: Deprecation Policy
description: Stability guarantees and deprecation timelines for assistant-ui features.
---

assistant-ui is committed to providing a stable API, so you can spend your time building amazing things on top of it.

Rarely, we need to deprecate a feature we've already shipped, because it is causing performance, usability, or security issues.
In such cases, we will communicate the intent to unship as soon as possible by marking the feature as `@deprecated` and publishing a notice in the documentation.

Deprecations and breaking changes primarily affect new features released. The longer an API has been in the library, the less likely it is to be deprecated.
For features that have long existed in the library, we will provide a longer deprecation notice period (as described below).

Below is a list of features considered stable and those considered experimental.

## Experimental Features

Experimental API carries the `unstable_` prefix and a `@deprecated` annotation recording the date it shipped:

```ts
/** @deprecated Experimental since 2026-09-05. Not scheduled for removal; the API may change in any release. */
```

The strikethrough your editor draws on these is a stability marker, not a removal notice. Experimental API ships from the same entry point as stable API, so the annotation is the only signal that reaches you while you type; read the hover text to tell the two kinds of strikethrough apart.

Each experimental API gets a three month window from the date it shipped, and it will not be removed inside that window. At the end of the window it is graduated to a stable name, removed, or explicitly extended with a new review date recorded in the same annotation:

```ts
/** @deprecated Experimental since 2026-06-14, extended 2026-12-05. Not scheduled for removal; the API may change in any release. */
```

Every declaration named `unstable_` is checked where it is written, so an unannotated one, a malformed tag, or a window that has closed without an extension fails CI. The dates in the source are current by construction.

- Anything marked as `unstable_`, `experimental_`, or `internal`
- The `RuntimeCore` API (considered internal)

## Beta Features

A deprecation of these features will undergo a short (&lt;1) month deprecation notice period.

- TailwindCSS Plugins (e.g. `tw-shimmer`, `tw-glass`)
- Context API
- Runtime API
- Message types
- Styled UI components
- Primitive Hooks (e.g. useBranchPickerNext)
- Attachment APIs
- shadcn/ui styles

## Stable Features

A deprecation of these features will undergo a long (&gt;3 month) deprecation notice period.

The following features are considered stable:

- Primitives (except for `AttachmentPrimitive`)
