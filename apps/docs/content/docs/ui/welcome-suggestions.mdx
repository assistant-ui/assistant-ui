`ThreadWelcomeSuggestions` renders starter prompts next to the composer of a new thread. Flat entries send their prompt on click; a group opens its items in place, navigated from the composer with a live prompt preview. Two layouts ship: a stacked vertical list (the default, ChatGPT-style) and a [pill row with a picker panel](#pills--picker). Either drops in next to any composer without wrapper elements or thread layout changes.

<Callout type="info">
  For runtime-generated prompts that appear after an assistant response, use
  [Follow-Up Suggestions](/docs/ui/follow-up-suggestions) instead.
</Callout>

## Getting Started

<Steps>
  <Step>

### Add `welcome-suggestions`

<InstallCommand shadcn={["welcome-suggestions"]} />

This adds a `/components/assistant-ui/welcome-suggestions.tsx` file to your project.

The default [Thread](/docs/ui/thread) already renders its own inline welcome pills from the static `Suggestions(...)` scope. When you adopt this component, remove that block (`ThreadSuggestions` in your `thread.tsx`) so the two don't render side by side.

  </Step>
  <Step>

### Provide suggestions

Pass entries through the `suggestions` prop:

- A **flat item** is `{ label, prompt? }` — `prompt` is the message that gets sent and defaults to `label`.
- A **group** is `{ label, icon?, suggestions }` — its items open in a second level instead of sending directly.

```tsx title="/components/assistant-ui/thread.tsx"
import {
  ThreadWelcomeSuggestions,
  type SuggestionEntry,
} from "@/components/assistant-ui/welcome-suggestions";

const WELCOME_SUGGESTIONS: SuggestionEntry[] = [
  {
    label: "Weather",
    icon: <CloudSunIcon />,
    suggestions: [
      {
        label: "in San Francisco",
        prompt: "What's the weather in San Francisco?",
      },
      { label: "in Tokyo", prompt: "What's the weather in Tokyo?" },
    ],
  },
  { label: "Compare React and Vue" }, // flat item; label doubles as prompt
];
```

When the prop is omitted, the component falls back to the flat welcome prompts configured with `Suggestions(...)` (see the [Suggestions guide](/docs/guides/suggestions)). Grouped entries always come from the prop. Dynamic follow-up prompts on `thread.suggestions` are never rendered here.

  </Step>
  <Step>

### Render next to the composer

Wrap it in `AuiIf` so the suggestions leave once the conversation starts:

```tsx title="/components/assistant-ui/thread.tsx" {4-6}
<ThreadPrimitive.ViewportFooter>
  <ThreadPrimitive.ScrollToBottom />
  <Composer />
  <AuiIf condition={(s) => s.thread.isEmpty}>
    <ThreadWelcomeSuggestions suggestions={WELCOME_SUGGESTIONS} />
  </AuiIf>
</ThreadPrimitive.ViewportFooter>
```

  </Step>
</Steps>

## Layouts

Both layouts compose the same `WelcomeSuggestionsRoot` and render the same entries; only the presentation differs. `ThreadWelcomeSuggestions` is shorthand for the stacked one.

Flat items send their prompt on click in either layout. Groups drill in: the stack shows the group's items where the list was, while the pill row opens a picker panel above it. Mixing the two kinds is fine, and with only flat entries no second level ever opens — the stack is a plain list of prompts and the pill row behaves like a classic suggestion chip row.

### Stacked (default)

A vertical list. Opening a group drills into its items in place.

```tsx
<WelcomeSuggestionsRoot suggestions={WELCOME_SUGGESTIONS}>
  <WelcomeSuggestionsStack />
</WelcomeSuggestionsRoot>
```

### Pills + picker

A horizontal pill row; opening a group replaces the row with a picker panel until it is dismissed.

```tsx
<WelcomeSuggestionsRoot suggestions={WELCOME_SUGGESTIONS}>
  <WelcomeSuggestionsPills />
  <WelcomeSuggestionsPicker />
</WelcomeSuggestionsRoot>
```

## Keyboard & behavior

Selecting a suggestion goes through `ThreadPrimitive.Suggestion`: by default it sends the prompt immediately; with `send={false}` on the root it places the prompt in the composer for editing. Clicking an item and pressing <kbd>Enter</kbd> on the highlighted item are the same action.

### Stacked list

The list is a single tab stop with one highlight shared by hover and the arrow keys. <kbd>↓</kbd> first navigates the composer text; once the caret has no text left to traverse, the next <kbd>↓</kbd> enters the list — the composer keeps focus the whole time, so typing at any point just resumes composing. Top-level rows stay passive and never intercept typing:

| Key                             | Action                                                               |
| ------------------------------- | -------------------------------------------------------------------- |
| <kbd>↓</kbd> / <kbd>↑</kbd>     | Move the highlight, ghost-previewing flat rows in the composer's placeholder; <kbd>↓</kbd> at the end of the composer text enters the list, and <kbd>↑</kbd> on the first row exits back into the composer |
| <kbd>→</kbd> / <kbd>Enter</kbd> | Open the highlighted group (<kbd>Enter</kbd> on a flat row sends it)  |
| <kbd>Esc</kbd>                  | Clear the highlight and the preview                                   |

### Pill row

Each pill is its own tab stop:

| Key                         | Action                                                                  |
| --------------------------- | ------------------------------------------------------------------------ |
| <kbd>←</kbd> / <kbd>→</kbd> | Move focus between pills                                                 |
| <kbd>↓</kbd>                | Open the focused group pill; at the end of the composer text, focus the first pill |
| <kbd>Enter</kbd>            | Activate the pill (opens a group, sends a flat one)                      |
| <kbd>↑</kbd> / <kbd>Esc</kbd> | Return focus to the composer                                           |

Horizontal arrow keys flip in right-to-left locales, in both layouts.

### While a group is open

In either layout, the composer keeps focus and drives the panel:

| Key                         | Action                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| <kbd>↑</kbd> / <kbd>↓</kbd> | Move the highlight (wrapping) and ghost-preview the prompt in the composer's placeholder; in the pills picker, <kbd>↑</kbd> on the top item exits to its pill |
| <kbd>Enter</kbd>            | Select the highlighted item (plain composer submit when nothing is highlighted)                                    |
| <kbd>Esc</kbd>              | Close the group; the stack re-highlights the group's row and the composer keeps driving the arrows                 |
| <kbd>Tab</kbd>              | Close the group and return to the suggestions (the stack's list or the group's pill)                               |
| Characters                  | Type into the composer; the group closes and the typed text stays                                                  |

A preview is ghost text in the composer's native placeholder, never the draft: hovering an item previews it just like the arrows do, it only shows while the composer is empty, and it inherits the placeholder styling of any composer with no extra setup. Typing, sending, and every way out of a panel leave the draft exactly as it was; only selecting an item commits, through the regular suggestion action.

## Props

**`ThreadWelcomeSuggestions`** / **`WelcomeSuggestionsRoot`**

- `suggestions`: the entries to render; falls back to the static `Suggestions(...)` scope when omitted.
- `send`: default `true`. Whether selecting an item sends the prompt immediately or only places it in the composer.

**`WelcomeSuggestionsStack`**

- `density`: `"comfortable"` (default) or `"compact"` for tighter rows.
- `separators`: default `true`; hairline dividers between rows, hidden around the highlighted row.
- `indicator`: the trailing glyph on action rows — flat rows and the open group's items — either `"send"` (the default while sending; flips in RTL), `"enter"` for a ↵ Return-key glyph, or `"none"` (the default with `send={false}`).
- `chevron`: default `true`; the trailing chevron on group rows (flips in RTL), independent of `indicator`.
- `className`: merged onto the listbox container.

**`WelcomeSuggestionsPicker`**

- `density`, `separators`: same as the stack, applied to the panel rows.
- `indicator`: the glyph revealed on the highlighted row — `"send"` (the default while sending), `"enter"`, or `"none"` (the default with `send={false}`).
- `children`: custom rows; defaults to one `WelcomeSuggestionsPickerItem` per item of the open group.

**`WelcomeSuggestionsPickerItem`**

- `prompt` (required) and `label`, plus `indicator`, `density`, `separators`, and any button props.

## Styling

Rows default to comfortable density with separators; group rows get a trailing chevron and action rows a send glyph — try the toggles in the demo above. The sub-level rows inherit `density`, `separators`, and the action glyph from the stack, and the stack mirrors the resolved `indicator` and `chevron` (plus any explicitly set `density` or `separators`) as `data-*` attributes on `[data-slot="aui_thread-welcome-stack"]` for CSS overrides.

```tsx
<WelcomeSuggestionsRoot suggestions={WELCOME_SUGGESTIONS}>
  <WelcomeSuggestionsStack density="compact" separators={false} />
</WelcomeSuggestionsRoot>
```

## Custom composition

Every building block is exported for your own arrangements: `WelcomeSuggestionsRoot`, `WelcomeSuggestionsStack`, `WelcomeSuggestionsPills`, `WelcomeSuggestionsPicker`, `WelcomeSuggestionsPickerItem`, and the `useWelcomeSuggestions` context hook for reading the open group and driving `openGroup`/`close` yourself.

An open panel dismisses on outside pointer-down; an outside control can call `event.preventDefault()` on its pointer-down to act on the open panel without dismissing it, the same opt-out Radix's `DismissableLayer` uses.

## Accessibility

Each layout renders a single-tab-stop listbox and reports the highlighted row through `aria-activedescendant`. While a group is open, DOM focus stays in the composer input, which advertises the panel via the editable-combobox ARIA pattern, so screen readers track the highlight without focus ever leaving the text field.
