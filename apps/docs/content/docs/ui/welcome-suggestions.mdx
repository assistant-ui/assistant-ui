`ThreadWelcomeSuggestions` renders starter prompts for an empty thread as a stacked vertical list, ChatGPT-style. Flat entries send on click; clicking a group swaps its items in place and hands navigation to the composer. A second layout, [pills + picker](#pills--picker-layout), renders groups as a horizontal pill row instead. Place either next to any composer; no wrapper elements or thread layout changes are required.

<Callout type="info">
  For runtime-generated prompts that appear after an assistant response, use
  [Follow-Up Suggestions](/docs/ui/follow-up-suggestions) instead.
</Callout>

<InstallCommand shadcn={["welcome-suggestions"]} />

  </Step>

### Provide suggestions

Pass entries through the `suggestions` prop. An entry with a `suggestions` array is a group; without one it is a flat item. When the prop is omitted, the component reads the static welcome prompts configured with `Suggestions(...)`. Dynamic follow-up prompts from `thread.suggestions` are never rendered here.

```tsx title="/components/assistant-ui/thread.tsx"
import {
  ThreadWelcomeSuggestions,
  type SuggestionEntry,
} from "@/components/assistant-ui/welcome-suggestions";

const WELCOME_SUGGESTIONS: SuggestionEntry[] = [
  {
    label: "Weather",
    icon: <CloudSunIcon />,
    suggestions: [
      {
        label: "in San Francisco",
        prompt: "What's the weather in San Francisco?",
      },
      { label: "in Tokyo", prompt: "What's the weather in Tokyo?" },
    ],
  },
  { label: "Compare React and Vue" }, // flat item; label doubles as prompt
];
```

  </Step>
  <Step>

### Render next to the composer

```tsx title="/components/assistant-ui/thread.tsx" {4}
<ThreadPrimitive.ViewportFooter>
  <ThreadPrimitive.ScrollToBottom />
  <Composer />
  <ThreadWelcomeSuggestions suggestions={WELCOME_SUGGESTIONS} />
</ThreadPrimitive.ViewportFooter>
```

  </Step>
</Steps>

## Behavior

Selecting a suggestion goes through `ThreadPrimitive.Suggestion`: by default (`send`) it sends the prompt immediately; with `send={false}` it places the prompt in the composer for editing. Clicking an item and pressing <kbd>Enter</kbd> on the highlighted item are the same action.

The list is a single tab stop with one highlight shared by hover and the arrow keys. Top-level rows stay passive and never intercept typing:

| Key                             | Action                                                                          |
| ------------------------------- | -------------------------------------------------------------------------------- |
| <kbd>↓</kbd> / <kbd>↑</kbd>     | Move the highlight                                                                |
| <kbd>→</kbd> / <kbd>Enter</kbd> | Open the highlighted group (<kbd>Enter</kbd> on a flat row sends it)              |

While a group is open, the composer keeps focus and drives the panel:

| Key                          | Action                                                                   |
| ---------------------------- | ------------------------------------------------------------------------ |
| <kbd>↑</kbd> / <kbd>↓</kbd>  | Move the highlight and live-preview the prompt in the composer            |
| <kbd>Enter</kbd>             | Select the highlighted item (plain composer submit when nothing is highlighted) |
| <kbd>Esc</kbd>               | Return to the top level with that group's row highlighted; arrow navigation continues |
| <kbd>Tab</kbd>               | Close the group and move focus on; the previewed prompt stays in the composer |
| Characters                   | Type into the composer; the group closes                                  |

Previewing writes over the composer, but a draft is never silently lost: <kbd>Esc</kbd> is cancel and puts the pre-open draft back, while <kbd>Tab</kbd> and selection accept what the picker wrote.

## Props

- `suggestions`: the entries to render; falls back to the static `Suggestions(...)` scope. Pass the prop for grouped entries.
- `send`: default `true`. Whether selecting an item sends the prompt immediately or places it in the composer.

## Styling

Rows default to comfortable density with separators and no group indicator (try the toggles in the demo above). Set the variants on `WelcomeSuggestionsStack` when composing:

- `density`: `"comfortable"` (default) or `"compact"` for tighter rows.
- `separators`: default `true`; hairline dividers between rows, hidden around the highlighted row.
- `indicator`: default `"none"`; `"chevron"` adds a trailing chevron to group rows (flips in RTL).
- `className`: merged onto the listbox container.

```tsx
<WelcomeSuggestionsRoot suggestions={WELCOME_SUGGESTIONS}>
  <WelcomeSuggestionsStack density="compact" separators={false} />
</WelcomeSuggestionsRoot>
```

The sub-level rows inherit `density` and `separators` from the stack. The stack mirrors `indicator`, and any explicitly set `density` or `separators`, as `data-*` attributes on `[data-slot="aui_thread-welcome-stack"]` for CSS overrides.

## Pills + picker layout

The alternative layout renders groups as a horizontal pill row; opening a group replaces the row with a picker panel. Compose it from the same root:

```tsx
<WelcomeSuggestionsRoot suggestions={WELCOME_SUGGESTIONS}>
  <WelcomeSuggestionsPills />
  <WelcomeSuggestionsPicker />
</WelcomeSuggestionsRoot>
```

Pills are tab stops: <kbd>←</kbd>/<kbd>→</kbd> move focus and <kbd>↓</kbd> or <kbd>Enter</kbd> opens a group; flat entries render as pills that send directly. The open panel behaves exactly like the stack's sub-level, driven by the composer with the same keys. `WelcomeSuggestionsPicker` accepts `density` and `separators`, so the panel can share the stack's look.

## Custom composition

The default export composes exported subcomponents you can arrange yourself: `WelcomeSuggestionsRoot`, `WelcomeSuggestionsStack`, `WelcomeSuggestionsPills`, `WelcomeSuggestionsPicker`, `WelcomeSuggestionsPickerItem`, and the `useWelcomeSuggestions` context hook.

When composing your own picker rows, `WelcomeSuggestionsPickerItem` accepts the same `density` and `separators` options as the stack.
