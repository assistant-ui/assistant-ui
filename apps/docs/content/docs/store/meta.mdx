---
title: Meta
description: Track scope origin with source and query.
---

Every scope accessor has three metadata properties: `source` and `query` describe where a scope comes from, and `name` is the scope's own name. They are reserved: scope methods cannot use these names. The function members `call`, `apply`, and `bind` are also reserved so accessors remain callable when a bundler lowers optional chaining.

```tsx
aui.thread.source; // "root" | the parent scope's name, e.g. "thread" | null
aui.thread.query; // {} | { index: 0 } | null
aui.thread.name; // "thread"
```

## Root scopes

When you fill a scope directly via a provider's `AuiConfig({ ... })`, it gets `source: "root"` and an empty `query`:

```tsx
const ThreadMetadata = () => {
  const aui = useAui();
  const source = aui.thread.source; // "root"
  const query = aui.thread.query; // {}
  return <pre>{JSON.stringify({ source, query })}</pre>;
};

const RootScope = () => {
  const config = AuiConfig({ thread: ThreadResource() });
  return (
    <AuiProvider config={config}>
      <ThreadMetadata />
    </AuiProvider>
  );
};
```

This is the default: the scope was provided directly, not derived from another scope.

## Derived scopes

When a scope is created via `Derived`, its `source` points to the parent scope it was derived from, and `query` carries the lookup parameters:

```tsx
const MessageMetadata = () => {
  const aui = useAui();
  const source = aui.message.source; // "thread"
  const query = aui.message.query; // { index: 0 }
  return <pre>{JSON.stringify({ source, query })}</pre>;
};

const DerivedScope = () => {
  const aui = useAui();
  const config = AuiConfig({
    message: Derived({
      source: "thread",
      query: { index: 0 },
      get: (aui) => aui.thread.message({ index: 0 }),
    }),
  });

  return (
    <AuiProvider extends={aui} config={config}>
      <MessageMetadata />
    </AuiProvider>
  );
};
```

You can declare the expected meta shape in `ScopeRegistry`:

```ts
declare module "@assistant-ui/store" {
  interface ScopeRegistry {
    message: {
      methods: {
        getState: () => { role: string; content: string };
      };
      meta: { source: "thread"; query: { index: number } };
    };
  }
}
```

This makes the `source` and `query` types precise: TypeScript will enforce that any `Derived` providing the `message` scope uses the correct source and query shape.

## Unavailable scopes

When a scope hasn't been provided by any `AuiProvider` above the current component, its accessor has `source: null` and `query: null`. `name` still answers; calling the accessor or reading a client method throws. Invoking it through `call`, `apply`, or `bind` also throws the scope error:

```tsx
aui.message.source; // null — no message scope in context
aui.message.query; // null
aui.message.name; // "message"
aui.message.getState(); // throws
```

The accessor itself is always truthy, so `if (aui.message)` does not tell you anything. Check availability through the `optional` view, which resolves an unavailable scope to `undefined`:

```tsx
if (aui.optional.message) {
  // scope is available
}
```

## Summary

| `source` | Meaning |
| --- | --- |
| `"root"` | Scope was filled directly via `AuiConfig({ ... })` |
| The parent scope's name, e.g. `"thread"` | Scope was derived from that scope via `Derived` |
| `null` | Scope is not available in the current context |
