### toEveInputResponse

Converts an assistant-ui tool approval response into an Eve `Answer`.

When `inputRequest` is known, every returned answer carries an option the
request declares, the literal `"approve"` / `"deny"` for an approval that
declares no options, or a free-form answer. A literal option match wins,
then the `"approve"` / `"deny"` option the response's boolean decision
names, then the response's `text` (or its `reason`, for a caller that
predates the first-class answer field) when the request takes a free-form
answer (`display: "text"`, `allowFreeform`, or no options at all, and never
`display: "confirmation"`) and the response is not a refusal.

A response the known request cannot record as the answer it asked for throws
instead of being submitted, because Eve resolves an interaction the moment
any answer for it arrives, and an empty one is recorded as an answer with no
content. Not sending leaves the interaction open, so the caller can retry or
the user can answer it as an ordinary message.

With no request to map against, a one-argument call forwards a caller
`optionId` as is and otherwise maps the decision to the literal `"approve"` /
`"deny"` option every Eve approval declares.

```ts
const toEveInputResponse: (response: RespondToToolApprovalOptions, inputRequest?: Interaction["request"]) => Answer;
```

### useEveAgentRuntime

Connects Eve's `useEveAgent` hook to assistant-ui's runtime contract.

The runtime renders Eve messages, forwards new user messages to the Eve
session, supports cancellation, and maps Eve interactions to assistant-ui
tool approval UI.

### useEveEvents

Read the authoritative Eve server event stream from the runtime extras.

```ts
const useEveEvents: () => EveRuntimeExtras["events"];
```

### useEveReset

Returns a function that starts a new Eve session: it stops reading the
current session and clears its events and messages, without cancelling a
turn still running on the server. Pending staged messages and tool execution
state are discarded. Safe to render
outside an Eve runtime; invoking the returned function there throws.

With `cloud`, it starts a new thread instead, leaving the current thread and its session in the list.

```ts
const useEveReset: () => () => void;
```

### useEveSession

Read the current Eve session cursor from the runtime extras. Persist it to
resume the session later via `initialSession`. `undefined` when no session
exists yet or outside an Eve runtime.

With `cloud`, each cloud thread already keeps its session, so there is nothing to persist.

```ts
const useEveSession: () => EveRuntimeExtras["session"] | undefined;
```
