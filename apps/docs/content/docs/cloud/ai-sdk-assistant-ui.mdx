title: AI SDK + assistant-ui
description: Connect the AI SDK runtime to Assistant Cloud for persisted threads, automatic titles, run reports, engagement events, feedback and attachments, with the assistant-ui components or headless.
---

`useChatRuntime` from `@assistant-ui/ai-sdk` wraps the AI SDK's chat transport and, given a `cloud`, adds everything the cloud offers a runtime. This is the integration most apps want: it works with the assistant-ui components, with the primitives, or headless, on React, React Native and Ink.

## What the runtime does with the cloud

1. **Threads.** The thread list is backed by the project: it lists, creates, renames, archives and deletes threads, and creates the cloud thread on the first user message.
2. **Persistence.** Every message is stored as it completes streaming, in the `ai-sdk/v6` format, and reloaded when the user opens the thread again. Edits and regenerations keep their branches.
3. **Titles.** After the first assistant response the project's thread title feature names the thread.
4. **Run reports.** Each response is reported with its status, outcome, error, duration, time to first token, steps and tool calls, and whatever model, usage and trace metadata the route provides. See [Run reports](/docs/cloud/telemetry).
5. **Engagement events.** Sends, edits, stops, regenerations, copies, branch switches, suggestions, attachments, thread switches, speech, voice and shown errors are recorded from the runtime's store. See [Engagement events](/docs/cloud/engagement).
6. **Feedback and attachments.** The `feedback` adapter defaults to cloud message feedback and the `attachments` adapter to cloud uploads; pass your own to replace either.

Every visited thread stays mounted, so a run in progress continues after the user switches threads and is still persisted and reported when it finishes.

### Create the client and the runtime

<PlatformTabs>
<Tab value="React">

```tsx title="app/chat/page.tsx"
"use client";

import { useMemo } from "react";
import { useAuth } from "@clerk/nextjs";
import { AssistantCloud, AssistantRuntimeProvider } from "@assistant-ui/react";
import { useChatRuntime } from "@assistant-ui/ai-sdk";
import { ThreadList } from "@/components/assistant-ui/elements/thread-list.aui";
import { Thread } from "@/components/assistant-ui/elements/thread.aui";

export default function ChatPage() {
  const { getToken } = useAuth();
  const cloud = useMemo(
    () =>
      new AssistantCloud({
        baseUrl: process.env.NEXT_PUBLIC_ASSISTANT_BASE_URL!,
        authToken: () => getToken({ template: "assistant-ui" }),
      }),
    [getToken],
  );

  const runtime = useChatRuntime({ cloud });

  return (
    <AssistantRuntimeProvider runtime={runtime}>
      <div className="grid h-dvh grid-cols-[240px_1fr]">
        <ThreadList />
        <Thread />
      </div>
    </AssistantRuntimeProvider>
  );
}
```

For a prototype, omit `cloud` altogether: with `NEXT_PUBLIC_ASSISTANT_BASE_URL` set, the runtime creates an anonymous client itself.

### Fill in model and usage on the route

The browser sees the stream, not the model behind it. A `messageMetadata` callback on the AI SDK route puts model, provider, usage and finish reason into the message metadata the runtime persists and reports:

```ts title="app/api/chat/route.ts"
import { convertToModelMessages, streamText } from "ai";
import { openai } from "@ai-sdk/openai";

export async function POST(req: Request) {
  const { messages } = await req.json();
  const model = openai("gpt-5.6-luna");
  const result = streamText({
    model,
    messages: await convertToModelMessages(messages),
  });

  return result.toUIMessageStreamResponse({
    messageMetadata: ({ part }) => {
      if (part.type === "finish") {
        return { usage: part.totalUsage, finishReason: part.finishReason };
      }
      if (part.type === "finish-step") {
        return { modelId: part.response.modelId, provider: model.provider };
      }
      return undefined;
    },
  });
}
```

[Run reports](/docs/cloud/telemetry#route-configuration) lists every key the runtime reads, and [Traces](/docs/cloud/traces) adds the trace id that joins the report to your server spans.

### Store hosts

Apps built on `AuiConfig` or `createAssistantClient` use `AISDKThreads({ cloud, scopeId, threadId, onThreadIdChange })` as their thread list resource. With `cloud` set it is a remote thread list with the same behaviour as above; `scopeId` follows the same account and workspace rules as on `useChatRuntime`, and `threadId` controls the selected thread and is ignored without `cloud`.

## What is reported

| Report field | Source on this runtime |
|---|---|
| `status`, `outcome_type`, `error`, `error_code` | the run's finish, the user's stop, and the route's `finishReason` |
| `first_token_ms`, `duration_ms`, per step `start_ms` and `end_ms` | measured by the runtime |
| `steps`, `tool_calls`, `tool_source` | the message parts; a step that called a tool gets `finish_reason: "tool-calls"` |
| `model_id`, `provider`, usage, `trace_id`, sampling calls | the route's `messageMetadata` |

The `"disconnected"` outcome and a real per step finish reason are the two things this runtime cannot see, because it observes the persisted message rather than the AI SDK finish event. Everything else on [Run reports](/docs/cloud/telemetry) applies.

## Feedback and attachments

With `cloud` set, two adapters default to the cloud and need no setup:

- **Feedback.** The feedback buttons of the assistant-ui message components submit a positive or negative rating on the stored message. It appears on the thread's page, counts into the satisfaction reading and can filter Threads; see [Message feedback](/docs/cloud/engagement#message-feedback).
- **Attachments.** `CloudFileAttachmentAdapter` takes any file the composer offers and leaves the type check to the project. Adding a file to the composer asks the project for a presigned upload URL, uploads the file with its content type, cancellable while pending, and attaches an `image` part for images or a `file` part with the object URL and MIME type for anything else. Images, PDF, plain text, CSV, RTF and the Office and OpenDocument formats are accepted up to 25 MB; a private bucket serves them back through 15 minute signed reads, which message lists apply for you when a thread is reloaded. The `attachment_added` and `attachment_failed` events are recorded for each file.

Pass `adapters: { feedback }` or `adapters: { attachments }` to replace either; the cloud adapters are defaults, not requirements. Uploading outside the composer goes through `cloud.files`; see [Files](/docs/cloud/api#files).

## Authentication

The examples above use a Clerk token on React and a token callback elsewhere; anonymous mode is the zero configuration option for a prototype. [Authentication](/docs/cloud/authorization) covers every provider, the token endpoint pattern, claiming anonymous threads after sign in, and allowed origins.

## Frameworks on this runtime

Anything that answers with an AI SDK UI message stream works with this page as written. A [Mastra](/docs/integrations/frameworks/mastra/overview) agent, behind a route or on its own server, takes `cloud` on the same `useChatRuntime` call, and so does any backend that returns `toUIMessageStreamResponse`. [Cloudflare Agents](/docs/integrations/frameworks/cloudflare-agents) is the exception: its guide wraps `useAgentChat` in `useAISDKRuntime`, which has no `cloud` option, and the conversation lives in the Durable Object.
