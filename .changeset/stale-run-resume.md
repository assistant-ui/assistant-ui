store a running assistant message in Assistant Cloud as soon as its run starts so its run lease stays alive while the tab streams it; a reply whose tab closed mid-run now loads as an interrupted error instead of disappearing, and the new `ActionBarPrimitive.Resume` continues it in a new assistant message. A tab that hides ends its runs as interrupted, and a run whose lease went stale or was resumed elsewhere gets no further writes, so nothing overwrites the resumed reply. The AI SDK runtime (`withFormat` history) holds run leases too when each thread message maps to one AI SDK message. A reply another tab is still writing shows as in progress and follows the run live until it finishes or is interrupted; the new `ActionBarPrimitive.RefreshRun` re-reads it on demand. Messages carry `runState` (`"stale"` or `"in-progress"`), `ErrorPrimitive.Root` exposes it as `data-run-state` (with `role="status"` while in progress), and `ActionBarPrimitive.Root` with `hideWhenRunning` also hides while another tab writes the reply. `useCloudThreadListAdapter` takes `runsContinueOnServer` for runtimes whose runs keep going on the backend after the tab leaves, so a closing page leaves their leases open; AG-UI agents that implement `connect()` report it on their own through the new optional `ThreadHistoryAdapter.unstable_setRunsContinueOnServer`.
