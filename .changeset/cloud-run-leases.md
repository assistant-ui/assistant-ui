add run leases to thread messages: `threads.runs` opens (`open`), keeps alive (`heartbeat`) and ends (`end`, with an optional reason, `interrupted` among them) a run, `open_run` on message create opens one with the message, `lease_id` on create and update writes as its holder, and listed messages carry their `run` state; `CloudMessagePersistence` opens a run for a message appended as running, heartbeats on the server's interval, ends it after the final write, ends the runs it holds as `interrupted` with a keepalive request when the page unloads (a page kept in the back/forward cache keeps its runs and heartbeats again when shown), drops a plain write refused with `run_in_progress` because another session runs the message, and stops writing a message whose lease was lost: a superseded run's first write is stored once on the sibling the server forks, and a stale, superseded or ended lease drops every later write; `createFormattedPersistence` passes a run phase through on append and update, so run leases work for any message format
