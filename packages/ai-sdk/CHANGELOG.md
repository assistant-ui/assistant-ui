# @assistant-ui/ai-sdk

## 0.0.4

### Patch Changes

- [#6748](https://github.com/assistant-ui/assistant-ui/pull/6748) [`9fa3778`](https://github.com/assistant-ui/assistant-ui/commit/9fa3778ed84ee3a43cbdc6cf57d0b323c51adb08) - fix(ai-sdk): stop re-sending a persisted message whose content is unchanged ([@okisdev](https://github.com/okisdev))
  
  returning to an earlier branch and continuing the conversation no longer re-sends an identical `update` for the messages already on that branch. with cloud persistence the redundant write for the user message was rejected with a 409 and retried on every later run stop. an update is now issued only when the encoded payload actually differs from what was last written.

- [#6705](https://github.com/assistant-ui/assistant-ui/pull/6705) [`bc75ef5`](https://github.com/assistant-ui/assistant-ui/commit/bc75ef57f40b50f3ab5f6fa47cdc4d761849f564) - fix: scope adapter refs to committed renders ([@Kinfe123](https://github.com/Kinfe123))

- [#6792](https://github.com/assistant-ui/assistant-ui/pull/6792) [`9322628`](https://github.com/assistant-ui/assistant-ui/commit/9322628c36d8dc86fa66359445aacfd2a00dc75a) - fix: carry server `messageMetadata` through to the thread ([@okisdev](https://github.com/okisdev))
  
  metadata keys the UIMessage carries outside the thread metadata shape (`usage`, `modelId`, anything a route returns from `messageMetadata`) now land in `metadata.custom` instead of being dropped by the message normalizer, so `useThreadTokenUsage` and the context display report the usage the documented route emits.

- [#6498](https://github.com/assistant-ui/assistant-ui/pull/6498) [`65d449b`](https://github.com/assistant-ui/assistant-ui/commit/65d449bf225e190f308de00f85196420b72dc6d4) - feat: keep cloud threads running across switches in AISDKThreads ([@okisdev](https://github.com/okisdev))
  
  The cloud thread list now opts into backgroundThreads: switching away no longer cancels an in-flight run (delete still stops it), every visited thread keeps its own mounted history, and new threads generate their titles automatically.
