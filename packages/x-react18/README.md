# @assistant-ui/x-react18

Runs a package's tests and published types against React 18, for packages whose `react` peer range is `^18 || ^19`.

It installs React 18 under aliased names (`react-v18`, `react-dom-v18` and their `@types`), so the workspace's React 19 is untouched.

- `react18()` from `@assistant-ui/x-react18/vitest` returns vitest config to merge over a package's own. A vite plugin resolves `react` and `react-dom` in inlined modules to React 18, and a Node resolve hook, loaded through `execArgv`, does the same for `require` and bare imports in `node_modules`, including inside `react-dom` and third-party libraries. In a package built on `@assistant-ui/tap`, `react` in the package's own modules resolves to tap's react-shim, as `aui-build` rewrites it; dependencies keep plain React 18. tap itself is left out, because its tests run its `src` and the shim would resolve to its built `dist`, a second copy of tap's runtime.
- `@assistant-ui/x-react18/tsconfig.json` maps `react` and `react-dom` types to React 18 and turns `skipLibCheck` off, since the check reads declaration files. Extend it together with the package's own tsconfig in `tsconfig.peer-react18.json` to check the published `dist/**/*.d.ts`.
- `aui-react18-types [project...]` runs `tsc` on each project (default `tsconfig.peer-react18.json`). It fails on errors in the package's own files. For errors inside `node_modules`, it type-checks the same files against React 19 and fails on any that only React 18's types introduce. It builds the package first when `dist` has no declarations, or when a project's resolved `include` or files reach into `dist` and `dist` is older than `src`. It fails a project whose resolved config doesn't map all of `react`, `react/*`, `react-dom` and `react-dom/*` to React 18's types, or has `skipLibCheck` on, which a tsconfig listed after the preset in `extends`, or an override, causes. Errors in declarations outside the package's own directory, in `node_modules` or a workspace dependency, count as upstream.

A package's `test` script runs only React 19. `test:peer-react18` and `test:types:peer-react18` run in `.github/workflows/react18-weekly.yaml`, weekly and on demand through `workflow_dispatch`, which can target any branch and a subset of packages. A failed weekly run comments on the open `react18-weekly` issue, or opens one, and the next passing weekly run closes it.
